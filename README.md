# 서랍

혼자 쓰는 **마감 · 필기 · 링크 · 파일** 앱. 언제까지 해야 하는 것을 달력으로 보고,
적어 둔 글과 모아 둔 주소와 첨부파일을 **한 서랍 안에 폴더로** 정리한다.
문장을 쓰면 **이 컴퓨터에서 도는 Llama**가 날짜와 제목을 뽑아낸다.
인터넷도, 로그인도, 외부 AI API도 쓰지 않는다.

## 깔아서 쓰기 (Windows)

1. **[seorap-setup.exe 받기](https://github.com/shinjaewon1105/seorap/releases/latest/download/seorap-setup.exe)**
   ([Releases](https://github.com/shinjaewon1105/seorap/releases/latest)) 를 받아 실행한다.
   관리자 권한 없이 내 계정에만 깔린다. "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행**.
2. AI 기능(문장으로 마감 넣기 · 메모 정리)을 쓰려면 [Ollama](https://ollama.com) 를 깔고
   `ollama pull qwen3.5:4b`. 없어도 나머지는 다 된다.
3. 다른 기기와 맞추기는 선택이다 — 설정에서 가입 → 이메일 확인 → 관리자 승인 뒤에 켜진다.
   휴대폰은 <https://seorap-80fc9.web.app>.

소스에서 돌리려면 Node.js 를 깔고:

```
npm install
npm start
```

화면은 둘뿐이다.

| | |
|---|---|
| **달력** | 첫 화면. 월간 한 판과, 오른쪽에 가까운 순으로 D-N 이 붙은 마감 목록 |
| **파일** | 윈도우 파일 탐색기처럼. 폴더 안에 **마감 · 필기 · 링크 · 첨부파일**이 나란히 |

마감 하나나 필기 하나를 열면 그 위에 화면이 덮이고, 왼쪽 위 **←** 로 돌아온다.

## 실행

바탕화면 `서랍` 폴더를 열고, 그 안의 **`서랍`** (파란 서랍 아이콘)을 더블클릭한다.
시작 메뉴에도 등록되어 있어서 **`Win` 키 → "서랍"** 을 쳐도 된다.

**작업 표시줄에 고정**하려면 창이 뜬 뒤 작업표시줄 아이콘을 우클릭 → 고정.

> 예전에 "일정"이라는 이름으로 고정해 둔 것이 있으면 그건 떼어내고 다시 고정해야 한다.
> 앱 이름과 폴더 이름이 모두 바뀌었다(2026-09-12).

`node_modules` 가 지워졌거나 다른 PC로 옮긴 경우에는 **`서랍 실행.bat`** 을 대신 쓴다.
필요한 파일을 먼저 내려받은 뒤 앱을 띄운다.

창의 X를 눌러도 완전히 꺼지지 않고 **트레이(시계 옆)** 로 내려간다. 알림을 계속
보내야 하기 때문이다. 완전히 끄려면 트레이 아이콘 우클릭 → **완전히 종료**.

### 필요한 것

| | |
|---|---|
| Ollama | 실행 중이어야 한다 (`http://127.0.0.1:11434`) |
| 모델 | `qwen3.5:4b` 하나로 다 한다 — 자연어 입력(설정에서 전환 가능) · 메모 AI 정리 · 파일 나누기 · 클래스룸 공지 읽기 |

> 부른다 — 안 정하면 생각에 토큰을 다 쓰고 빈 답을 낸다. 클래스룸 공지만 생각 모드를 켠다
> (상대 날짜를 맞히려고). 2026-10-12 에 llama 모델을 모두 지우고 2026-10-27 에 바꿨다.
| Node.js | 처음 설치할 때만 필요 |

Ollama가 꺼져 있어도 앱은 정상 동작하고 자연어 입력만 안 된다.
설정 화면에서 연결 상태를 확인할 수 있다.

## 달력 (첫 화면)

달력은 **일 월 화 수 목 금 토** 순서다. 한 칸을 두 번 누르면 그 날짜에 새 마감이 생긴다.
칩을 다른 날짜로 끌면 날짜가 바뀐다. 반복 마감을 끌면 **이 일정만 / 이후 모두**를 묻는다.

오른쪽 **마감 목록**은 늘 떠 있다. 가까운 순으로 묶여 있고 (지났음 · 오늘 · 이번 주 ·
이번 달 · 나중에 · 끝냄), 각 줄에 **D-DAY / D-3 / +2일** 이 붙는다.
체크하면 흐려지고 취소선이 그어진다. `끝낸 것` 을 누르면 끝낸 마감도 보인다.

> **시간과 장소는 쓰지 않는다.** 모든 항목이 날짜 단위다 (2026-09-12에 뺐다).
> 예전에 넣어 둔 시간·장소 값은 자료에 그대로 남아 있지만 화면에는 나오지 않는다.

## 자연어 입력

달력 화면 위 입력줄에 문장을 쓰고 **Enter**. 미리보기 카드가 뜨고, 고칠 게 있으면
그 자리에서 고친 뒤 **Enter를 한 번 더** 누르면 등록된다.

```
다음주 화요일까지 적분 수행평가 제출
내일 국어 발표
9월 30일 원문샘 발표
```

### 왜 두 겹인가

Llama의 역할은 **문장 → JSON 구조화** 하나로 한정했다. 3B 정도의 작은 모델은
"다음주 화요일" 같은 날짜 계산을 자주 틀리므로, 모델이 뽑아낸 날짜를
`renderer/nl.js` 의 한국어 해석기가 다시 계산해 **덮어쓴다.**
모델은 무른 일(무엇이 제목이고 무엇이 날짜 표현인지)을 하고, 정확성은 코드가 책임진다.

## 클래스룸 — 과제가 저절로 들어온다

학교 클래스룸의 과제가 **마감으로 저절로 들어온다.** 앱을 켤 때와 3시간마다 가져온다.
설정 → **클래스룸** 에 마지막으로 가져온 시각과 결과가 한 줄로 나오고,
`지금 가져오기` 로 손수 돌릴 수도 있다. 막히면 그 줄이 빨갛게 이유를 적는다.

- 과제 하나가 마감 하나다. `클래스룸 › <수업 이름>` 폴더에 들어가고, 기한은 클래스룸 날짜 그대로다
- 이미 지난 과제와 기한 없는 과제는 들이지 않는다
- 선생님이 기한을 바꾸면 따라간다. **내가 날짜를 옮겨 둔 마감은 건드리지 않는다**
- 제출하면 끝냄으로 바뀐다. 끝냄을 다시 풀어 두면 그대로 둔다 — 제출 상태가 **바뀐 순간에만** 고친다
- 서랍에서 지운 과제는 다시 들어오지 않는다
- **공지 글 속 날짜**(시험 · 준비물 · 발표 · 대회)는 로컬 모델이 뽑아 `클래스룸 › 확인 필요` 에 넣는다.
  날짜는 한국어 해석기가 공지가 올라온 날 기준으로 다시 계산한다. 맞으면 옮기고, 아니면 지운다

### 어떻게 이어져 있나

```
학교 계정의 Apps Script 웹 앱  (gas/클래스룸/Code.gs — 클래스룸 읽기 권한만)
      ↑ POST { 비밀값 }               ↓ 과제 · 내 제출 상태 · 최근 3주 공지 (JSON)
PC 서랍  main.js (가져오기 · 공지 읽기)  →  renderer/classroom.js (마감으로 맞추기)
```

- 웹 앱 주소와 비밀값은 **`data/classroom.json` 에만** 있다. 화면 쪽으로 넘기지 않고,
  설치 파일(`npm run dist`)에도 들어가지 않는다. 이 파일이 없으면 클래스룸은 통째로 꺼진다
- 비밀값은 주소가 아니라 POST 본문에 실린다. 주소는 이곳저곳 기록에 남는다
- 비밀값을 바꾸려면 Apps Script 프로젝트 설정의 스크립트 속성 `SECRET` 을 지우고
  `setup()` 을 다시 돌린 뒤, 로그에 찍힌 새 값을 `data/classroom.json` 에 넣는다
- 웹 앱 코드를 고치면 `배포 → 배포 관리 → ✏ → 버전: 새 버전` 으로 올려야 반영된다 (주소는 그대로)
- 공지 읽기는 **생각 모드 + 도구 호출**로 한다. 생각 모드에 JSON 스키마(`format`)를 같이 주면
  생각이 끝나지 않는다 — 공지 한 편에 275초를 쓰고 빈 답을 냈다. 지금은 한 편에 10~30초

설계와 시험 기록은 `gas/설계.md` 에 있다.

## 파일 — 윈도우 탐색기처럼

**파일** 탭은 탐색기처럼 쓰게 맞췄다. 자주 쓰는 것은 차림표 안에 숨기지 않고
**명령 줄에 내놓았다** — 뒤로 · 앞으로 · 위로, 새로 만들기 · 파일 연결,
잘라내기 · 복사 · 붙여넣기 · 이름 바꾸기 · 삭제, 정렬 · 보기 · AI 정리.
고른 게 없으면 눌리지 않는다(눌러 놓고 아무 일도 안 나는 게 제일 답답하다).
자판도 탐색기와 같다 — `F2` `Delete` `F5` `Backspace` `Ctrl+A/C/X/V`,
`↑↓` `Home` `End`, `Shift+↑↓` 로 범위, **글자를 치면 그 이름으로 건너뛴다.**

**파일** 탭은 이 앱의 정리대다. 폴더 안에 **마감 · 필기 · 링크 · 첨부파일**이
종류를 가리지 않고 나란히 들어간다. 쓰는 법은 윈도우 파일 탐색기와 같다.

- 왼쪽에 **폴더 나무**, 오른쪽에 그 폴더의 내용. 폴더를 **두 번 누르면 들어간다**
- 위쪽 **주소 줄**(서랍 › 적분)의 어느 조각이든 눌러서 그리로 간다.
  `↑` 또는 `Backspace` 는 위 폴더로, **`Alt+←`** 는 방금 있던 자리로
- 머리글(이름 · 종류 · 크기 · 수정한 날짜)을 누르면 그 기준으로 **정렬**된다
- 오른쪽 위 단추로 **자세히 ↔ 큰 아이콘**
- `Ctrl+클릭` · `Shift+클릭` · `Ctrl+A` 로 **여러 개 고르기**,
  고른 것을 폴더(나무 · 목록 · 주소 줄 어디든) 위로 **끌어다 놓으면 옮겨진다**
- **`Ctrl+C` / `Ctrl+X` / `Ctrl+V`** 로 복사 · 잘라내기 · 붙여넣기.
  폴더를 복사하면 안의 것까지 통째로 복사된다
- `F2` 이름 바꾸기, `Delete` 삭제, `Enter` 열기, `↑` `↓` 로 고르기
- 오른쪽 위 칸에 몇 글자 적으면 **이 폴더 아래 전부에서** 찾는다
- **컴퓨터에서 파일을 끌어다 놓으면** 그 폴더에 바로 연결된다 (원본은 그 자리에 그대로).
  받을 자리가 없는 곳 — 달력 위, 알림 위 — 에 놓아도 버리지 않고 `서랍` 맨 위에 넣고
  `보기` 단추로 짚어 준다(필기 화면에서는 그 필기가 든 폴더로)

### 오른쪽 단추

빈 자리에서 누르면 **새로 만들기** 차림표가 뜬다.

| | |
|---|---|
| 새 폴더 | 이 폴더 안에 |
| 새 마감 | 오늘 날짜로 만들고 바로 연다 |
| 새 필기 | 빈 필기를 만들고 바로 연다 |
| 새 링크 | 주소를 물어보고 담는다 (제목은 알아서 가져온다) |
| 컴퓨터 파일 연결… | 탐색기 창을 열어 고른다 (원본은 그 자리에) |
| 붙여넣기 · 전체 선택 · 보기 전환 | |

항목 위에서 누르면 열기 / 잘라내기 / 복사 / 이름 바꾸기 / 다른 폴더로 / 삭제,
그리고 종류에 따라 **탐색기에서 보기 · 이 마감 열기 · 끝냄 표시 · 주소 고치기**.
폴더 위에서는 **이 안에 새 폴더 · 이 안에 파일 연결 · 폴더만 풀기 · 폴더째 삭제**.

> 폴더는 **앱 안에서만** 있는 것이다. 여기서 아무리 옮겨도 디스크의 파일은
> 제자리에 그대로 있다. `삭제`도 앱에서 떼어내는 것이고(앱 폴더의 사본은 휴지통으로),
> 원본 연결은 연결만 끊는다.

### 마감에 넣은 첨부도 여기 있다

마감 화면에서 파일을 첨부하면 **그 마감이 들어 있는 폴더에 함께 놓인다.**
그래서 파일 화면을 열면 마감과 그 첨부가 나란히 보인다.
파일 줄에 붙은 회색 글씨가 그 파일이 딸린 마감이고, 누르면 그 마감이 열린다.

### AI 정리

`✦ AI 정리` 를 누르면 **어떻게 나눌까** 를 한 줄로 물어본다.
"과목별로", "제출한 것과 아닌 것으로" 처럼 적으면 그대로 따르고, 비우면 파일 이름만 보고 나눈다.
모델은 **어느 파일을 어느 폴더에** 만 정하고, 이름 대조는 앱이 한다 —
목록에 없는 이름을 지어내면 버리고, 언급하지 않은 파일은 있던 자리에 그대로 둔다.
결과가 마음에 안 들면 토스트의 `되돌리기`.

## 마감 하나

달력의 칩이나 마감 목록, 파일 화면에서 마감을 누르면 열린다.

| 줄 | |
|---|---|
| 날짜 | `‹ ›` 로 하루씩, 가운데를 누르면 달력 팝업 |
| 끝냄 | 체크하면 목록에서 흐려진다. 반복 마감은 회차마다 따로 |
| 마감 아닌 그냥 일정 | 수업이나 약속처럼 D-N 이 필요 없는 것 |
| 폴더 | 이 마감을 어느 서랍 칸에 둘지 |
| 반복 | 평소엔 접혀 있다. 매일/매주/매월/매년 + 종료일 |
| 알림 | 당일 아침 9시 · 하루 전 · 이틀 전 · 일주일 전 · 시각 직접 지정 |

그 아래로 **메모 · 링크 · 첨부파일**.

### 체크리스트

메모에 `- [ ]` 로 적으면 체크박스가 되고, **눌러서 켜고 끌 수 있다.**
누르면 원본 Markdown의 `[ ]` ↔ `[x]` 가 바로 바뀐다.
제목 옆에 **`2 / 5`** 처럼 진행 상황이 뜨고, 다 끝내면 초록으로 바뀐다.
코드 블록 안에 적은 `- [ ]` 는 세지 않는다.

### 메모 (Markdown)

메모 칸을 **클릭하면 원본 편집**, `Ctrl+Enter` 또는 바깥 클릭으로 다시 보기.
제목·굵게·목록·인용·표·구분선, 그리고 —

- **수식** — `$E=mc^2$` 는 줄 안에, `$$...$$` 는 가운데 큰 글씨로 (KaTeX)
- **코드** — ` ```python ` 으로 시작하면 색이 입혀진다
- **이미지·파일** — 마감 화면 어디에나 끌어다 놓거나 `Ctrl+V`

필기 화면도 **똑같은 메모 칸**을 쓴다 (`renderer/mdbox.js` 하나로 둘이 함께).

### AI 정리 — 적어둔 걸 Markdown으로

`✦ AI 정리` 는 **내가 쓴 걸 서식만 입혀 다시 내놓는다.** 내용을 지어내지 않는다.
대충 적은 수식(`루트 2`, `1/3 적분`)도 KaTeX 문법으로 바꿔 준다.

결과를 적용하기 전에 **앱이 원문과 대조한다.**

- 원문에 있던 **숫자가 결과에 없으면** 빨간 칸으로 짚어 준다
- 사라진 낱말을 굵게 나열한다 (조사는 붙었다 떨어지므로 앞부분만 같아도 남은 것으로 친다)
- `루트 → \sqrt` 처럼 우리가 시킨 변환은 손실로 치지 않는다
- 결과가 원문보다 2배 넘게 길면 "없던 내용이 붙었을 수 있다" 고 알린다
- `빠진 것 채우기` 를 누르면 빠진 조각을 짚어 주고 한 번 더 돌린다 (두 번까지)

판단은 사용자가 한다. `바꾸기` / `아래에 붙이기` / `버리기` 중에 고른다.

## 필기

파일 화면에서 `새 필기` 로 만들고, 폴더 안에 마감·링크와 나란히 놓인다.
제목 · 폴더 · 📌 고정 · 삭제, 그 아래 메모 칸과 링크 칸.
제목도 내용도 링크도 없는 필기는 화면을 떠날 때 조용히 지워진다.

## 링크

파일 화면에서 `새 링크` 로 주소를 담으면, 그 페이지의 `<title>` 을 읽어 제목으로 채운다.
못 읽어 와도 주소는 이미 저장돼 있다. 누르면 **기본 브라우저**에서 열린다.

**마감 안에도, 필기 안에도** 링크 칸이 있다. 거기 담은 링크는 그 마감·필기에만
붙어 있고, `＋` 를 누르면 파일 화면으로 빼낼 수 있다.

## 첨부파일

**컴퓨터의 파일은 언제나 원본 연결이다**(2026-11-01). 원본 자리에 그대로 두고 경로만
기억한다. 앱 폴더로 사본을 만드는 "가져오기"와 `앱 안으로 들여오기`, 설정의
"파일 가져오기 기본값" 은 없앴다. 끌어다 놓기 · `파일 연결` 단추 · 차림표가 모두 같은 길이다.

`data/attachments/` 에 파일이 생기는 건 **원본이 없는 것뿐이다** — 붙여넣은 그림,
브라우저에서 끌어온 그림, 다른 기기가 올린 파일. 예전에 가져온 사본도 그대로 열린다.
파일 화면의 복사·붙여넣기는 디스크에 사본을 만들지 않고 같은 파일을 하나 더 가리킨다.

연결한 원본이 **감시 폴더**(바탕화면 · 문서 · 다운로드) 안에서 옮겨지거나 이름이
바뀌면 다시 찾아 붙는다. 감시가 알려 준 경로부터 맞춰 보고(1초 안), 앱이 꺼져 있던 사이
옮긴 것은 감시 폴더 전체를 **비동기로** 훑어 찾는다 — 사라진 목록이 바뀌었거나 30분이 지났을 때만.
같은 파일인지는 NTFS 파일 ID **+ 크기**, 또는 내용 지문(앞 1MB + 크기의 SHA-1)으로 본다.
못 찾으면 빨갛게 `파일 없음` 으로 표시된다.

- ⚠ 파일 ID 만으로 고르면 안 된다. Node 가 64비트 ID 를 보통 숫자로 줘서 뒷자리가 잘리고
  지운 파일의 ID 를 새 파일이 물려받아 겹친다 — 지운 파일의 기록이 엉뚱한 파일에 붙었다.
- ⚠ 전체 훑기를 동기로 돌리면 앱이 굳는다(3만 개에 1.4초). 예전에는 사라진 파일이 하나만
  있어도 2분마다, 바탕화면이 바뀔 때마다 그랬다.
- 디스크 정보(경로 · 없음 표시 · 크기 …)는 메인이 바꿀 때 `diskAt` 을 찍는다. 화면이 낡은
  목록을 통째로 저장해도 메인이 더 나중에 안 것은 지킨다(`keepDiskState`).
  `diskAt` 은 기기마다 다른 사정이라 클라우드에 올리지 않는다.
- 디스크에서 파일이 고쳐져도 **앱에서 바꿔 둔 이름은 남긴다.**

## 클라우드 — 어느 기기에서든

Firebase 를 붙이면 **PC 앱과 휴대폰 브라우저가 같은 자료를 봅니다.**
남은 단계는 같은 폴더의 **`FIREBASE-설정.md`** 에 있습니다.

`renderer/firebase-config.js` 가 비어 있으면 클라우드는 통째로 꺼지고,
앱은 예전처럼 이 PC 안에서만 돕니다. 붙였다 떼도 자료는 그대로 있습니다.

**첨부파일 내용을 올릴지는 따로 켭니다.** 같은 파일 맨 아래의
`window.FIREBASE_STORAGE` 가 그 스위치다. Firebase Storage 는 카드 등록(Blaze)을
요구해서 **지금은 꺼져 있습니다.**

### 어떻게 맞추나

- 항목(마감·필기·링크·파일)마다 **`updatedAt` 이 늦은 쪽이 이깁니다.**
  두 기기에서 같은 것을 고쳤으면 나중에 고친 쪽이 남습니다
- 지운 것은 **흔적(tomb)** 을 남깁니다. 이게 없으면 다른 기기가 "지웠다"와
  "아직 못 받았다"를 구별하지 못해 지운 것이 되살아납니다. 흔적은 한 달 뒤 스스로 사라집니다
- 인터넷이 끊겨도 그냥 씁니다. 다시 붙으면 알아서 맞춥니다 (Firestore 오프라인 저장)
- 설정 → 클라우드 → `지금 맞추기` 로 손수 한 번 돌릴 수도 있습니다

### 첨부파일

첨부파일의 **이름과 자리**(어느 폴더, 어느 마감)는 늘 맞춰집니다.
갈리는 건 **파일 내용**을 어디에 두느냐입니다. 스위치는 `firebase-config.js` 에 있습니다.

| 스위치 | 어디에 |
|---|---|
| `FIREBASE_STORAGE = true` | Firebase Storage. 제대로 된 길이지만 카드 등록(Blaze)이 필요합니다 |
| `FIREBASE_BLOBS = true` | **Firestore 에 조각내서.** 카드 없이 가는 길 — 지금 쓰는 쪽입니다 |
| 둘 다 `false` | 안 올립니다. 파일은 만든 컴퓨터에만 남습니다 |

**Firestore 에 담는 방식** (`renderer/cloud.js`):

- 문서 하나가 1MB 까지라 파일을 **700KB 씩 잘라** `users/{uid}/blobs/{id}/parts/{n}` 에 넣습니다.
  base64 로 말지 않고 binary(`Blob.fromUint8Array`) 그대로라 크기가 부풀지 않습니다
- 머리글(`blobs/{id}`)에 크기·조각 수가 있습니다. **조각을 다 넣은 뒤 맨 마지막에** 씁니다 —
  중간에 끊겨도 "반쯤 올라간 파일" 로 보이지 않게
- **한 개 5MB, 한 사람 100MB.** 총량은 규칙이 셀 수 없어서 앱이 지킵니다(`meta/usage`)
- 무료 몫 1GB 를 가입한 사람 전부가 나눠 씁니다

**원본 연결한 파일도 올라갑니다.** 디스크의 원본은 그 자리에 그대로 두고
내용만 클라우드에도 둡니다 — 앱 폴더에 사본을 만들지는 않습니다.
원본을 고치면 크기·수정시각(`cloudSig`)이 달라지는 걸 보고 알아서 다시 올립니다.
(예전의 `앱 안으로 들여오기` 는 2026-11-01 에 없앴습니다.)

### 누가 쓰나

문이 셋이다. **가입 → 이메일 확인 → 관리자 승인.**

1. 설정 → 클라우드 → `가입`. 비밀번호는 두 번(8자 이상), 확인 메일이 한 통 간다
2. 메일의 링크를 누른다. 앱이 5초마다 스스로 물어봐서 저절로 넘어간다
3. 관리자가 승인하면 그 자리에서 바로 넘어간다 (다시 켜지 않아도 된다)

**관리자는 `config/admin` 문서 하나로 정한다. 처음 등록한 한 사람이 임자고,
앱에서는 바꿀 수 없다**(고치려면 콘솔에서 그 문서를 지운다). 그래서 가입을 열어 두어도
아무나 관리자가 되지 않는다.

관리자 화면은 설정의 **회원 승인** 칸이다 — 신청한 사람 목록, 승인 · 승인 취소 · 지우기.

어느 문에서 막혔는지가 화면에 그대로 적힌다. **"그냥 안 됨" 으로 끝나지 않게 하는 게
이 설계의 요점이다.** 확인·승인 전에도 이 기기 안에서는 평소대로 다 쓸 수 있다.

사람마다 `users/{uid}` 아래만 보이고, AI 도 각자 자기 PC 를 쓴다.

### 휴대폰에서 열기

```bash
npm run web
npx firebase login
npx firebase deploy
```

`npm run web` 이 `renderer/` 를 브라우저용으로 `web/` 에 옮겨 담고,
`firebase deploy` 가 그걸(과 보안 규칙을) 올립니다. 주소가 나오면 휴대폰에서 그 주소를 열고
설정에서 같은 이메일로 로그인하면 됩니다. 홈 화면에 담으면 앱처럼 열립니다.

> **보안 규칙을 한 번은 꼭 올려야 합니다.** Firestore 를 프로덕션 모드로 만들면
> 기본 규칙이 "전부 막음"이라, 올리기 전에는 로그인해도 아무것도 안 맞춰집니다.

### 휴대폰에서 AI 쓰기 — PC를 거친다

Llama 는 이 PC 안에서 돕니다. 휴대폰이 그걸 쓰려고 **바깥으로 포트를 여는 일은
하지 않았습니다** — 그건 집 컴퓨터를 인터넷에 내놓는 일입니다.

대신 **파이어베이스를 우체통으로 씁니다** (`renderer/ai-relay.js`).

```
휴대폰  →  users/{uid}/ai 에 "이것 좀 해 주세요" 를 적어 둔다
PC 앱   →  그걸 집어다 Llama 를 돌리고, 답을 그 자리에 적는다
휴대폰  →  답을 받아 쓰고, 쪽지를 지운다
```

- 열리는 구멍이 하나도 없습니다. 오가는 건 전부 로그인한 자기 자리 안입니다
- **PC 앱이 켜져 있고 같은 계정으로 로그인돼 있어야** 됩니다.
  PC 앱은 1분마다 `meta/worker` 에 "켜져 있음" 을 적고, 휴대폰은 그걸 보고 판단합니다
- 안 켜져 있으면 그냥 *"PC 앱이 꺼져 있습니다"* 라고 말합니다. 기다리게 두지 않습니다
- 되는 것은 PC와 같습니다 — 자연어로 마감 적기, 메모 AI 정리, 파일 AI 정리
- 다만 **글자가 흐르듯 나오지 않고** 다 되면 한 번에 나옵니다
- 두 대가 켜져 있어도 한 대만 집습니다 (트랜잭션으로 먼저 집는 쪽이 임자)
- 20분 넘게 답을 못 받은 쪽지는 PC 앱이 치웁니다

### 보안

`firestore.rules` 가 세 겹으로 막습니다.

1. **자리** — `users/{내 uid}` 아래의 **정해진 칸에만** 쓸 수 있습니다.
   그 밖의 경로는 규칙 자체가 없어서 전부 막힙니다(기본이 거부)
2. **사람** — 로그인해야 하고, **이메일/비밀번호로 들어온 토큰**이어야 합니다
   (`request.auth.token.firebase.sign_in_provider == 'password'`)
3. **모양** — 문서마다 칸 수와 글자 수에 뚜껑이 있습니다.
   문서 이름과 안에 적힌 `id` 도 같아야 합니다

그리고:

- `firebase-config.js` 의 값은 브라우저에 그대로 실리는 **공개 값**입니다.
  숨길 필요가 없고, 실제 보호는 위 규칙이 합니다
- 비밀번호는 어디에도 적혀 있지 않습니다. 설정 화면에서 직접 넣습니다
- **규칙은 "로그인한 사람"까지만 봅니다.** 비밀번호가 새면 규칙은 도움이 안 됩니다
- 콘솔에서 **가입(Enable create)을 꺼 두세요.** 안 그러면 남이 이 프로젝트에
  계정을 만들 수 있습니다 (자기 자리만 보이므로 회원님 자료는 못 봅니다)

```
│  ├─ store.js          ← 마감·필기·링크·파일 자료
│  ├─ cloud.js          ← Firebase 로 기기끼리 맞추기 + 첨부파일 담기
│  ├─ ai-relay.js       ← 휴대폰의 AI 부탁을 PC 앱이 받아서 돌린다
│  ├─ firebase-config.js ← 클라우드 설정 (비어 있으면 꺼짐)
│  ├─ web-shim.js       ← 브라우저에서 Electron 의 api 를 대신한다
│  └─ vendor/           ← marked · DOMPurify · KaTeX · highlight.js (전부 로컬)
└─ build/icon.ico
```

**백업**은 `data` 폴더를 통째로 복사하면 된다. 다른 PC로 옮길 때는 폴더 전체를
복사한 뒤 `서랍 실행.bat` 을 한 번 돌린다. (`node_modules` 는 빼도 된다)

## 잘 안 될 때

| 증상 | 볼 곳 |
|---|---|
| 자연어 입력이 안 된다 | Ollama가 떠 있는지. 설정 화면 아래에 연결 상태가 나온다 |
| AI 정리가 오래 걸린다 | 보통 3~5초다. 훨씬 오래 걸리고 빈 답이 오면 그 요청에 `think: false` 가 빠진 것이다 |
| 첨부가 `파일 없음` | 원본을 감시 폴더 밖으로 옮겼을 수 있다. 설정에서 그 폴더를 감시 폴더에 추가 |
| 수식이 빈칸으로 보인다 | 글꼴 문제다. 앱을 다시 켜면 `markdown.js` 가 KaTeX 글꼴을 다시 불러온다 |
| 창이 안 뜬다 | 트레이(시계 옆)에 내려가 있을 수 있다. 아이콘을 눌러 되살린다 |
| 클라우드가 안 맞는다 | 설정 → 클라우드에서 상태를 본다. 로그아웃됐으면 다시 로그인 |
| 휴대폰에 옛 화면이 뜬다 | `npm run web` 후 `npx firebase deploy` 를 다시 한다 |
| 화면이 이상하다 | `F12` 로 개발자 도구를 열어 콘솔을 본다 |
| 모델을 바꿨더니 AI가 다 죽었다 | 설정이 지운 모델을 가리키면 `useModel()` 이 설치된 것으로 바꾸고 설정도 고쳐 둔다 |
| 끌어다 놓기가 안 먹는다 | 콘솔에서 드롭 순간의 오류를 본다. 2026-11-01 까지는 `detail.js` 가 `tree.js` 의 `isAttDrag` 를 그냥 불러 ReferenceError 로 죽었다 |

### 시험할 때

- ⚠ **`node_modules/electron/dist/electron.exe 다른폴더` 로 열어도 진짜 앱이 뜬다.**
  옆의 `resources/app` 디딤돌이 있으면 Electron 은 경로 인자를 무시한다. 그래서 사본을 만들어
  시험한다고 믿었는데 실제 `data/events.json` 에 시험 첨부가 들어갔다(2026-11-01, id 로 골라 지움).
  격리하려면 `dist` 를 `resources/app` 만 빼고 다른 곳에 복사해서 그 electron.exe 로 연다.
  또 그 폴더 옆에 `app.js` 같은 파일이 있으면 Electron 이 폴더 대신 그걸 연다.
- 드롭은 CDP `Input.dispatchDragEvent` 로 진짜처럼 시험할 수 있다(`--remote-debugging-port`).
  실패한 끌기 뒤에는 `dragCancel` 을 보내야 다음 시험이 꼬이지 않는다.
  `dragOperationsMask` 를 1(복사만)로도 꼭 해 본다 — `dropEffect='link'` 로 못박으면 거기서 거부된다.
